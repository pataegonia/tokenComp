## 5. 누적 결과와 검산

- 기존 양의λ46점은 원본 로그 SHA-256이 이전 집계와 모두 일치했다.
- 새로 완료된15평가 중 λ0 한 점을 제외한14점을 더해 **양의λ60점·16계열**, λ0는 별도1점이다.
- 신규15평가의 최종 checkpoint step, 정렬·스케줄·공간 Context·채널 그룹과 실제 bitstream 평가 설정을 확인했다.
- 신규15평가에서 `Score + MSH y + MSH z + mean + container`가 전체 actual bytes와 로그 정밀도 내에서 일치했다.
- 받은23개 학습 시작 로그의 λ·분할·minimal/kernel5/STE·GPU2/batch2/누적2·새50k 및 model/data seed가 해당 계획과 일치했다.
- 구조 pilot과 seed 쌍의 제출 state에 저장된 실행 파일 해시가 현재 로컬 코드와 모두 일치했다.
- traceback, CUDA OOM, 저장 공간·할당량 오류, checkpoint 쓰기 오류, 시간 제한 종료 등 검사한 치명 오류 패턴은 없었다. DDP unused-parameter/gradient-stride, IterableDataset 길이, torchvision 경고는 있었다.

진행률은 마지막 완전한 progress 줄에서 계산했다. 전송 중 잘린 마지막 줄은 제외했다. `epoch×ceil(33017/2)+floor(epoch batch/2)`를 사용하며, 완료15개는 마지막 줄과50k 종료 메시지를 함께 대조했다. 현재 구조 세 모델은 모두 epoch0이므로 진행 step은 `floor(batch/2)`다. tqdm의 epoch 내 백분율을 전체50k 진행률로 쓰지 않았다.

표의 잔여 시간은 **받은 로그 시점**의 평균 batch 속도로 계산한 학습 잔여다. 큐 대기·평가·다운로드 이후 경과 시간은 포함하지 않는다. 로그가 없는 job의 실시간 상태는 아래처럼 서버에서 확인할 수 있다.

```bash
squeue -j 457786,457787,457788,457789,457828,457829 -o '%.18i %.24j %.10T %.30R %E'
```
